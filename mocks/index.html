Three ways the shelf could look

Static mocks, no build step, nothing wired to a real game. Frames render at true 390 × 844 and 1180 × 740, so what you read is what a device would render. Every direction carries a light/dark switch, because the repo tests both and a direction that only works in one is not a direction.

Status — most of this now ships

These mocks were the argument. The argument was accepted, and M1–M6 of plans/2026-08-27-1-plan-skin-layer.md are built: two skin families with four graded palettes, both home layouts, the appearance picker, per-game icon art, and the music layer. Run the real thing with node tools/serve.mjs — it is no longer a sentence over an empty page.

They are kept because the reasoning below is still the reasoning, and because a direction is easier to argue with as a picture than as a diff. Where a mock and the shipped app disagree, the app is right — it had to survive contrast grading, axe in four palettes, and twenty real game pages.

The two axes, kept separate

Each direction pairs a look with a structure, but the two are independent — you can take B's structure with C's palette. Say which half you like and I will recombine.

Axis 1 — the look

B matches the commissioned art: near-black gallery ground, each game's own accent. C does the opposite: warm paper and hairline rules so the art is the only loud thing on screen.

Axis 2 — what the home page is for

B is today-first: it opens on what you were doing and what is waiting. C is a shelf: a browsable index that argues for the games in words, because "you can re-check the result yourself" is the real differentiator and no icon says it.

Running these

From the fun worktree: node ../../../fun/tools/serve.mjs serves dist/, but these mocks need the repo root instead. Any static server rooted at the repo will do — the pages reference brand/ and art/ relative to mocks/, and ../assets/ for the fonts. Opening mocks/index.html over file:// also works for everything except the audio in some browsers.
