## Problem Statement

A complete, self-contained single-file HTML5 fruit-merge game (Suika/watermelon genre, "Orchard
Drop") was delivered for inclusion on the `fun.croft.ing` shelf. It draws everything on a canvas at
runtime and inlines the Matter.js 0.19.0 physics engine (MIT © @liabru) with its license notice
intact. Zero external requests, zero build step, zero extra assets.

It is **not** a Croft-native (Tier-1) game: it is physics-driven, not determinism-first, and produces
**no verifiable outcome record** (no move-list → `state_hash`, no re-checkable `?r=` share). So it
cannot be Tier-1 and must not pretend to be. It fits the **Tier-2** posture exactly: an already-
packaged, ethical, self-contained bundle, honestly represented as fun-but-unverifiable and served
contained in our chrome.

## Reasoning

- **Tier-2, not Tier-1.** The `docs/BUILDING-GAMES.md` §9 filter holds: fully client-side/static,
  non-extractive (no ads/analytics/telemetry — verified), redistribution-licensed (AGPL-3.0 first-
  party code + MIT Matter.js), fits the `GameModule` contract, honestly represented. This is the
  self-contained JS/canvas class §9 prefers — **not** the Emscripten + runtime-untar class it warns
  against.
- **Provenance is first-party + one dependency.** Unlike Astray/HexGL/Clumsy Bird (upstream repos),
  Orchard Drop's own code is original to the shelf; the one redistributed third-party component is
  Matter.js. The meta/attribution credit both honestly: author "the Croft shelf, with physics by
  @liabru's Matter.js", `basedOn` the Suika Game (Watermelon Game), license "AGPL-3.0 (game) · MIT
  (Matter.js)", `upstreamUrl` → the public repo (which also satisfies the AGPL source-offer).
- **Containment over the brief's PWA assumptions.** The integration brief assumed a service-worker
  PWA with `localStorage`-backed best score. This repo has **no service worker** (static per-game
  pages, offline via cache) and mounts wraps in an **opaque-origin sandboxed iframe**
  (`allow-scripts`, no `allow-same-origin`). Consequences, accepted as the honest containment cost:
  the game's `localStorage` best-score read/write throws in the opaque origin and is already
  try/catch-wrapped, so it fails silently (best resets per session; our-origin storage stays
  untouched, which the gate asserts). No SW/precache step is needed or added.

## Verified Assumptions

- Matter.js MIT header present at the top of the first inline `<script>` (lines 142–146) — kept
  verbatim; the engine block is never edited.
- `localStorage` access is try/catch-wrapped (`loadBest`/`saveBest`) → no uncaught error bubbles into
  our page under the sandbox. Containment gate confirms zero off-origin egress + no crashes.
- Only one vendor patch was needed: a §9 keyboard-focus re-grab (window `load` + capture-phase
  `pointerdown` → `window.focus()`) so arrow keys / Space keep reaching the frame after the player
  clicks our surrounding chrome. Recorded in `tier2.meta.json` patches.
- The game is genuinely playable at 360px and desktop, mounts its `#gameCanvas`, and the merge ladder
  works (guide shot `orchard-crate` captured a lived-in crate with real merges, score 46).

## Notes / follow-ups

  containment model, not a bug). If cross-session best is ever wanted for wraps, it would need a
  shelf-provided, sandbox-safe scores API (out of scope here).
- E2E was run on chromium only (this environment has no WebKit build); CI runs both engines.
