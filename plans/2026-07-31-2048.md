## Problem Statement

The shelf's shipped Tier-1 games (solitaire, match-3, bubble, wyrdle) are all
single-player, determinism-first, zero-networking. Wyrdle was the last pick on
the authoritative fun-list that needs no live connection; the higher-fun picks
(Four-in-a-Row, Reversi, …) are multiplayer and gated on the P2P transport
(cribbage stays gated until iroh). **2048** keeps the proven single-player
recipe moving: it is the cleanest next Tier-1 build (a build-fresh candidate in
`client-side-static-game-candidates.md` §A), needs no external data, and its
outcome is verifiable by move-list replay.

Objective: slide the 4×4 board (↑↓←→); equal tiles that collide merge into their
sum; a new tile spawns after every move that changes the board; reach the **2048
tile** to win; the game ends when no move changes the board (stuck). Score = the
running sum of merge values (the compare metric, surfaced like bubble).

Goal: `/2048/` meets every standard in `docs/BUILDING-GAMES.md` + the checklist.

## Reasoning

- **Build fresh.** 2048 (Gabriele Cirulli, MIT) is trivially rebuildable; the
  rules are far simpler than any integration, and building is the only path to a
  verifiable outcome + our identity. No name trap (2048 is not trademarked; we
  use the number).
- **Directional input, core decides legality.** The move is one of four
  `Direction`s — a tiny enum, so `(seed, moves)` replays exactly. The tap-first
  floor is four on-screen arrow buttons; swipe + physical arrow/WASD keys mirror
  them. A direction that does not change the board is **illegal** (no-op, no
  spawn) — the core decides; an E2E asserts the no-op (the guardrail).
- **Determinism = seeded spawns.** The one source of randomness is the
  post-move tile spawn (value 2 at p≈0.9 / 4 at p≈0.1, at a random empty cell).
  It derives from a **seeded ChaCha20 RNG** (the exact `DetRng` pattern
  `bubble-core`/`match3-core` use — `usize`→`u32` at the RNG boundary so
  native==wasm), advanced deterministically per spawn, so replay re-derives
  every spawn. Tiles are stored as **exponents** (`u8`: 0 = empty, else `v` where
  the tile value is `2^v`) — integers only, no floats on the hashed path.
- **Win / end.** `won` = any tile reaches exponent 11 (2048). The game **ends**
  when the board is full and no direction changes it (stuck) — a verifiable
  `Lost`-shaped completion carrying the final score; or the player ends early via
  "I'm done". Reaching 2048 flags `won` and surfaces the win; play may continue
  for a higher score (v1: reaching 2048 shows the verifiable win; "keep going" is
  a `TODO`). Score is surfaced (secondary metric), no stars — `pond-outcome`
  needs no change (bubble proved `Replayed{score:Some, stars:None}`).
- **No solver.** Every seed is *playable* (a non-full board always has a legal
  move), so — like wyrdle — the daily "pack" is a deterministic **seed schedule**
  (a seeded shuffle) with **no winnability search**; whether you reach 2048 is
  skill, not seed. The pack keeps the machinery (`pond-docformat` envelope,
  `{seeds, fixture}`, byte-identical regen, wasm-embedded, daily-indexed); the
  fixture is a short scripted `(seed, directions)` line used to prove replay in
  tests + the E2E (not a full 2048 win — reaching 2048 is ~hundreds of moves,
  impractical as a committed fixture; win detection is unit-tested via a crafted
  board instead).
- **Game isolation.** 2048 owns `crates/twenty48-core`, `crates/twenty48-wasm`,
  `src/games/2048/`, `games/2048/`. (Crate names use `twenty48` — a Rust crate
  name can't start with a digit; the game id / URL / registry use `2048`.) It
  touches shared files only at wiring points.

## Verified Assumptions

- **`DetRng` pattern to mirror** (`crates/bubble-core/src/rng.rs`): ChaCha20
  seeded from a `u64`, `index(len)` samples a `u32` range (width-stable for
  native==wasm) and counts draws; draws fold into the hash. (Read 2026-07-31.)
- **`pond-outcome` needs no change** for score-without-stars: `Replayed` fields
  are `pub`; `Record.score`/`stars` are `skip_serializing_if=Option::is_none`.
  (Verified during the wyrdle build.)
- **The full Tier-1 template** (core→wasm→TS→outcome→pack→howto→e2e→gate) is the
  freshly-built **wyrdle** shape (`crates/wyrdle-{core,wasm}`, `src/games/wyrdle/`,
  `games/wyrdle/daily-pack.json`, `tests/wyrdle.spec.ts`) plus **bubble** for the
  seeded-RNG + score-surfaced result. Both read 2026-07-31 during the wyrdle
  build. The shared wiring points (registry, how-to-registry, build.mjs,
  build-wasm.sh, tokens.css, chrome.test/drawer.spec counts, README) are known.
- **Crate-name-starting-with-digit is illegal** in Cargo/Rust; `twenty48` is the
  crate name, `2048` the game id (confirmed: Rust identifiers can't lead with a
  digit).

### Phase T1 — core: board + seeded spawn + move/merge + hash
**Goal:** the deterministic engine — slide/merge in four directions with seeded
spawns, score, win/stuck, a `state_hash`; golden-pinned; a `from_rows` test ctor.
**Changes:**
- [ ] `crates/twenty48-core/Cargo.toml` (member; deps mirror bubble-core:
  rand, rand_chacha, serde, serde_json, sha2, hex, thiserror).
- [ ] `src/rng.rs` — `DetRng` (copy the bubble-core pattern verbatim).
- [ ] `src/board.rs` — `Board` (4×4 `u8` exponents, `0`=empty), `Pos`,
  `from_rows` (test/solver ctor), `cells`, `get`, `is_full`, accessors.
- [ ] `src/engine.rs` — `Direction {Up,Down,Left,Right}`; `slide(board, dir) ->
  (changed, score_gain)` implementing compact→merge-once-per-pair→compact per
  line in travel order; `spawn(board, rng)` places a 2 (p≈0.9) / 4 (p≈0.1) at a
  seeded empty cell; `has_any_move`, `max_exponent`.
- [ ] `src/hash.rs` — `state_hash(board, draws, score)` (tag + dims + draws +
  score + cells; LE u32).
- [ ] `src/lib.rs` — `#![warn(missing_docs)]`, re-exports, a `mode` (WIDTH=4,
  HEIGHT=4, WIN_EXP=11, START_TILES=2, P_FOUR handling).
- [ ] `tests/golden.rs` — pinned merge cases (dedupe order; a double-merge row
  `[2,2,2,2]→[4,4]`; a no-merge slide; win at exp 11) + a pinned hash.
- [ ] `Cargo.toml` workspace member.
**Wiring test:** `golden.rs` — `slide` on crafted `from_rows` boards matches
hand-derived results (incl. `[1,1,1,1]` left → `[2,2,0,0]` in exponents = two
merges, score += 2·(2²)=8) and `state_hash` matches a pinned golden. RED first.
**Test edges:** merge-once (`[1,1,1,0]` left → `[2,1,0,0]`, not `[2,0,0,0]` and
not merging the produced tile again); direction symmetry (a right move is the
mirror of left); a full board with a legal merge is **not** stuck; a full board
with no equal neighbours **is** stuck; win at exp 11; spawn value distribution is
seed-deterministic (two runs identical; an RNG off-by-one flips the hash).
**Depends on:** nothing.
**Read-set:** `crates/bubble-core/src/{rng,hash,board,lib}.rs`.
**Write-set:** `crates/twenty48-core/**`, `Cargo.toml`.
**Shared-state contract:** edits shared `Cargo.toml` (member add) — merge-time only.
**Observability:** `slide` returns `changed`; illegal (unchanged) moves are a
typed no-op, never a panic; `Direction` is a plain enum.
**Done when:** (1) crafted boards slide/merge/score/win/stuck per the pinned
goldens; spawns are seed-deterministic. (2) `cargo test -p twenty48-core` +
fmt + clippy clean.
**Validation:** Narrow — golden + unit over pure functions.

### Phase T2 — core: `Game` wrapper + `pond-outcome` binding
