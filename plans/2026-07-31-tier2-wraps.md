# Tier-2 wraps — the first shipping wrapped games + the reusable harness

**Status:** 📋 **Pass 1+2 (2026-07-31).** Recon done; plan drafted. Not yet
executing past Phase 0. Branch: `claude/tier2-wraps` (in `fun/`, off clean
`main`). Builds three Tier-2 games — **Astray → HexGL → Clumsy Bird** — and, with
the first of them, ships the reusable **containment/legibility harness** and the
**honest-representation chrome** that the Tux Racer spike
(`plans/2026-07-30-tux-racer-wrap-spike.md`) only drafted. This is the recovery
path after the SuperTuxKart wrap was **cut/failed 2026-07-31**

## Problem Statement

`fun.croft.ing` is a two-tier shelf (COHESION §62). Tier 1 (Croft-native,
verifiable) has five shipped games. **Tier 2 has zero shipped games and no
reusable machinery** — the Tux Racer spike drafted the standard (T3 containment
harness, T4 honest representation) but shipped no code, and the first real
attempt at a Tier-2 game, **SuperTuxKart, failed and was cut** on 2026-07-31.

The STK failure is instructive and bounds this plan:

- STK was a **bucket-C Emscripten port** with a **"download ~130 MB → untar
  assets at runtime → populate the emscripten FS"** loader. The tar downloaded
  and reassembled fine (valid 217 MB `ustar`), but the upstream port's pinned
  `js-untar@2.0.0` Web Worker threw, so `run()` was never called and the canvas
  stayed black. Fixing it meant patching someone else's emscripten port.
- **Lesson (already written in `TODO/supertuxkart.md`):** the first *shipping*
  Tier-2 game must avoid the emscripten + runtime-asset-untar class entirely.
  Pick a **self-contained, pure-JS / Three.js bundle** that vendors as plain
  static files with no custom loader step, permissively licensed.

So this plan does two things at once, because the shelf needs both: it ships the
**first Tier-2 games** *and* it turns the drafted standard into **reusable,
shipped machinery** (a wrap primitive + a parameterized harness + an honesty
chrome + a `BUILDING-GAMES.md` addendum) that every future Tier-2 game reuses.

Goal: **Astray, HexGL, and Clumsy Bird are playable** at `/astray/`, `/hexgl/`,
`/clumsybird/`, each mounted through the drawer contract, **honestly represented**
as wrapped arcade games with no verifiable record, and each **passing a
real-browser containment/legibility gate** — with the wrap primitive, the harness,
and the Tier-2 standard all reusable and documented.

## Reasoning

- **Three candidates chosen after a primary-source recon (see Verified
  Assumptions), not the `[UNVERIFIED]` inventory.** The candidates doc named
  HexGL "the lowest-risk first Tier-2 exemplar"; recon confirmed HexGL (MIT) and
  surfaced that **Astray is even cleaner** (public domain, ~10 static files, no
  trademark), making it the ideal pathfinder. The originally-mooted trivial picks
  (Pacman-canvas, T-Rex Runner) were **rejected**: Pac-Man is a live Namco/Bandai
  trademark, and pacman-canvas additionally ships an `ads.txt`, a Sqlite3
  highscore backend, and hot-linked external sounds — three hits on the
  non-extractive gate. Clumsy Bird (GPL-3.0, self-contained, original name)
  replaces it.
- **Astray is the pathfinder, not HexGL — deliberately.** The first shipping
  Tier-2 game's real deliverable is the *reusable machinery*, not the game. The
  cheapest game to prove that machinery on wins the slot: Astray is public
  domain, ~10 files, no aging-toolchain risk. HexGL (impressive but ~2012
  Three.js, "in hiatus") and Clumsy Bird then **reuse** the primitive + harness,
  so their risk is isolated to their own bundle, not the shared standard.
- **Containment is the whole game for Tier-2.** We are running **untrusted
  third-party code in our chrome**. The webxdc/Cure53 lesson (recorded in the
  Tux Racer spike T3) is that **CSP alone does not contain a webview** — the
  containment must be `iframe[sandbox]` (opaque origin) **plus** a
  request-interception egress allowlist proven in a real browser, not assumed.
  The harness is the gate that replaces Tier-1's verifiable-outcome standard.
- **Honesty is non-negotiable on a verifiable-outcome shelf.** Four of five
  Tier-1 games carry a re-verifiable `?r=` record. A wrapped game has none, and
  the shelf **must say so** — a persistent "wrapped arcade game · no verifiable
  record" banner + attribution (title, author, license, upstream link), so the
  pond's "a result is checked, not trusted" property stays truthful and Tier-2
  never *looks* verifiable when it isn't.
- **Vendor, don't fetch; commit the bundle.** STK's runtime asset download was
  the failure surface. Tier-2 bundles here are vendored into the repo as static
  files (with a `VENDOR.md` provenance record + the upstream license verbatim)
  and served from our own origin — no runtime fetch of third-party assets, no
  untar step, offline after first load by construction.
- **Reuse the existing chrome-agnostic contract; extend it minimally.**
  `GameModule` (`mount`/`unmount`) already hides presentation from the game. The
  only contract change Tier-2 needs is an honesty signal on `GameEntry`
  (`tier`/`verifiable` + attribution) and a shared `mountWrappedGame` primitive;
  no per-game bespoke mounting.

  - `src/contract.ts` — `GameModule { mount(container, services); unmount() }`;
    `GameServices { mode: "drawer"|"fullscreen"|"standalone" }`; `GameEntry {
    id, title, icon, status: "playable"|"soon", load? }`.
  - `src/registry.ts` — `REGISTRY: readonly GameEntry[]`, `findGame(id)`. Games
    are added as one entry with a `load` factory.
  - `build.mjs` — emits `/<id>/index.html` per id in `GAME_PAGES` (body carries
    `data-game="<id>"`); copies `assets/` recursively to `dist/assets`; copies

    copy exists yet** — Tier-2 vendor dirs need a copy step added here.
- **Browser driver:** the Chrome extension is disabled in this workspace;
  **Playwright** is the driver (`@playwright/test` v1.61.x under
  `croft-pwa/node_modules`; browsers cached at `~/Library/Caches/ms-playwright`).

- **Egress reality in this sandbox:** live third-party network egress is blocked
  here (the STK recon noted browser egress is blocked for large loads). This does
  **not** affect Tier-2 games — they are vendored and served from our own origin,
  so the harness asserts *absence* of egress, which is testable offline.

## Concurrency Map

```
Sequential spine:
  Phase 0 → Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5 → [Phase 6 || Phase 7] → Phase 8
```

Phases 0–5 are strictly sequential: each builds on the prior (contract →
primitive → pathfinder game → harness → standard). The harness (Phase 4) must be
green on Astray before HexGL/Clumsy Bird are attempted, so a wrap that can't pass
the gate is caught on the cheapest game.

**Parallel set {6, 7}** (HexGL, Clumsy Bird) — *opt-in, only after Phase 5*:
- **Disjoint write-sets:** Phase 6 writes `src/games/hexgl/**`,
  `vendor/hexgl/**` (or `src/games/hexgl/vendor/**`), and its one registry line
  + one `build.mjs` copy line + one how-to entry. Phase 7 writes the analogous
  `clumsybird` paths. The only overlap is `src/registry.ts`, `build.mjs`,
  `src/how-to-registry.ts`, `src/games/tier2-manifest.ts` (the harness's game
  list) — **shared files**. Because of that overlap, **run them sequentially by
  default**; parallelize only in isolated worktrees with a disciplined local
  `git merge` back (per `execute.md` §4), and expect trivial conflicts on those
  4 shared files. Given each is small, **sequential is the recommended default**;
  the parallelism is documented as available, not mandated.
- **Shared-state contract:** both build wasm-free (Tier-2 is JS/WebGL, no Rust
  crate), bind no ports beyond the Playwright test server, write only under their
  own game dir + the 4 shared wiring files. Neither runs `git checkout` in the
  parent worktree.
- **Re-entry verification (if parallelized):** parent-repo HEAD == pre-dispatch
  SHA; `git worktree list` shows only expected worktrees; `git status` clean in
  main worktree; both games appear in `REGISTRY` after merge; harness green for
  both.

All other phases: sequential — each reads what the prior wrote.

## Phases

### Phase 0: Discovery — prove the containment approach runs the games
**Goal:** Before committing to the `iframe[sandbox]` + egress-allowlist design,
confirm firsthand that (a) each vendored game actually *runs* under the chosen
sandbox flags, (b) the flags that make it run still contain it, (c) build.mjs can
serve a vendored dir, and (d) Playwright can intercept/deny egress. This is the
STK-lesson insurance: the previous failure was a loader assumption that only
broke at runtime.

**Discovery tasks:**
- [ ] **D1: Does Astray run inside `iframe[sandbox="allow-scripts"]` (opaque
  origin), and does it need `allow-same-origin` / storage?**
  - **Probe:** Vendor Astray into a throwaway `dist/_spike/astray/`, serve it,
    load it in an `iframe` with `sandbox="allow-scripts"` via Playwright; check
    the canvas renders and keyboard input reaches it. Then tighten/loosen flags
    to find the minimal set. Record whether it touches `localStorage` (opaque
    origin makes that throw).
  - **Success criteria:** A concrete minimal `sandbox` flag string under which
    Astray renders + is playable, and a note on whether any storage/same-origin
    is required. If `allow-same-origin` is required, record the containment
    tradeoff (it re-grants our origin — mitigate by serving the bundle from a
    separate path and relying on the egress allowlist + no-DOM-access assertions).
  - **Disposition:** `keep-as-fixture` — the spike mount informs the real
    `mountWrappedGame` primitive; the `dist/_spike/` tree is throwaway.
- [ ] **D2: Can Playwright assert "no network egress outside an allowlist"?**
  - **Probe:** With the D1 mount loaded, use `page.route('**', ...)` to log every
    request; confirm all requests are same-origin to our dist server; craft an
    assertion that fails if any request targets a non-allowlisted host.
  - **Success criteria:** A working request-interception assertion pattern that
    is GREEN for a contained game and RED if a request escapes the allowlist
    (prove the RED by temporarily pointing an `<img>` at an external host).
  - **Disposition:** `promote` — becomes the egress assertion in the Phase 4
    harness.
- [ ] **D3: Does HexGL's ~2012 Three.js run as-is, or need a shim?**
  - **Probe:** Vendor HexGL into `dist/_spike/hexgl/`, serve, load in a real
    browser via Playwright, check the menu renders and a race starts without
    fatal console errors.
  - **Success criteria:** Either "runs as-is" or a concrete list of what breaks
    (named console errors / missing globals) so Phase 6 can scope the shim. This
    de-risks the impressive-but-old candidate before Phase 6 commits to it.
  - **Disposition:** `throwaway` (findings recorded; real vendor happens in
    Phase 6).
- [ ] **D4: build.mjs vendor-copy shape.**
  - **Probe:** Confirm the simplest way to copy `src/games/<id>/vendor/` (or a
    top-level `vendor/<id>/`) into `dist/<id>/vendor/` alongside the existing
    per-game `cp` lines; confirm the sandboxed iframe `src` resolves under the
    per-game base URL the build already uses (`base: "/"`).
  - **Success criteria:** A decided vendor location + the one-line copy pattern
    that lands the bundle at a URL the iframe can load.
  - **Disposition:** `promote` — becomes the Phase 3 build.mjs change.
**Done when:** D1–D4 answered with firsthand evidence; Verified Assumptions +
the Phase 1–6 designs updated for anything a probe contradicts (esp. the sandbox
flag set and the HexGL shim scope). Decision checkpoint with the owner if D1/D3
change the approach materially.
**Read-set:** `build.mjs`, `playwright.config.ts`, `tests/*.spec.ts` (as
patterns), the three upstream repos.
**Write-set:** `dist/_spike/**` (throwaway), scratch spec files under
`tests/_spike/`. No production files.
**Shared-state contract:** no shared mutable state beyond a local static server
port for Playwright; no git branch ops in the parent.

### Phase 2: The reusable wrap primitive — `mountWrappedGame`
**Goal:** A single shared helper that every Tier-2 `GameModule` uses to mount its
vendored bundle in a contained sandboxed iframe and tear it down cleanly.
**Changes:**
- [ ] `src/wrapped-game.ts` (new, SHARED) — `mountWrappedGame(container, {
  src, title, sandbox, allow })` creates the `iframe[sandbox=...]` (flag set from
  Phase 0/D1), sets `title` for a11y, appends it, and returns a teardown that
  removes the iframe and nulls references. No game-specific logic.
- [ ] Unit tests (RED first): the primitive creates an iframe with the expected
  sandbox attribute + src, and teardown removes it and leaves no listeners.
**Call chain:** a Tier-2 `GameModule.mount()` → `mountWrappedGame(...)` →
iframe in the container; `unmount()` → the returned teardown.
**Wiring test:** covered end-to-end by Phase 3's Astray URL test (the primitive
has no user-facing surface of its own; it is proven live by the first game that
uses it). Its unit tests prove the iframe/teardown contract.
**Depends on:** Phase 0 (sandbox flags), Phase 1.
**Read-set:** `src/contract.ts`, Phase 0 findings.
**Write-set:** `src/wrapped-game.ts`, its unit test.
**Shared-state contract:** none beyond the DOM container it's handed.
**Risks:** teardown must cancel anything the iframe can leak into our page — but
an opaque-origin iframe *cannot* reach our page, so teardown is just iframe
removal; assert no residual nodes/listeners after mount→unmount×N.
**Done when:**
1. **Behavioral:** calling the primitive mounts a contained iframe; teardown
   removes it with no residue after repeated cycles.
2. **Verification:** the primitive's unit tests green via `npm run test`.
**Validation:** Narrow — unit tests sufficient; the live proof is Phase 3.
