# Match-3 parity — Track B4: the 2×2 fish

**Status:** planning (2026-07-31). Parent: `plans/2026-07-30-match3-parity-roadmap.md`
(Track B / B4). Builds on B0–B3 (the special overlay + creation + striped/wrapped/
colour-bomb activation). B4 adds the **fish** — the first special from a **2×2 square**
match, which (owner decision, Option A) is folded into `find_matches` as a first-class
match. It is the heaviest phase: it **breaks the "match/legality core stays
byte-identical since B0" invariant**, so it re-locks vectors *and* re-checks
winnability broadly, and it introduces the first **seeded-`DetRng` activation**
(fish targeting).

## Problem Statement

Candy-Crush parity (roadmap D4 / B4) needs the **fish**: a 2×2 block of one colour
makes a fish; an activated fish **swims to a target cell and clears it**, preferring
cells that advance the objective (jelly, then blockers). B4 must:

- make a **2×2 same-colour square a first-class match** (Option A): it makes a swap
  legal, clears (leaving one fish), and is avoided by the deal + reshuffle — so every
  "is this a match?" consumer (clear, legality, `has_legal_move`, deal-avoidance,
  reshuffle) agrees, from **one** source of truth (`find_matches`);
- **create a fish** from a pure 2×2 (a new `SpecialKind::Fish`, tag `0x05`), rendered
  + labelled like the other specials;
- **activate a fish deterministically** — a matched/swapped fish draws a target from
  the seeded `DetRng` (prefers jelly → blockers → any gem, in a pinned order), clears
  it, chains, cascades; the draw folds into `draws`/`state_hash` so replay reproduces
  it exactly;
- stay **winnable-daily + honestly par'd** — the match-core change re-deals every
  board (fill now avoids 2×2s) and shifts play, so all packs regenerate and the
  winnability guarantee is re-checked.

## Positioning

A generic of the match-3 / Candy-Crush mechanic set (roadmap "Positioning"):
behaviour mirrors the reference (2×2 → fish; fish eat objective cells). Option A
(2×2 inside `find_matches`) is the owner-chosen **engineering** realization — the
reference does not dictate internal representation; A keeps "what is a match" a
single source of truth so every downstream path stays consistent for free.

## Reasoning

- **Option A — 2×2 is a match in `find_matches` (owner-decided 2026-07-31).** A new
  `find_squares` finds every 2×2 monochrome block; `find_matches` returns the line-run
  cells **∪** the square cells. Because every consumer (clear, `swap_legal`,
  `has_legal_move`, `legal_swaps`, deal-avoidance, `reshuffle_if_dead`) already reads
  `find_matches`, they all learn about 2×2s at once — no parallel detector to drift.
  The cost is scope: the dealt board changes (fill must avoid 2×2s too), so packs +
  fixtures + vectors re-lock broadly. Accepted for correctness (single source of truth).
- **Fish creation (B4.1).** A **pure 2×2** (a component with no ≥3 line run) creates a
  `Fish`; the four cells clear except one survivor (the fish), like every other
  creation. Priority stays **colour-bomb (≥5) > wrapped (L/T) > striped (4) > fish
  (2×2) > none (3)** — a region with a line shape makes that line special, not a fish
  (a 2×2 has no line-3, so a pure 2×2 never collides with a line component). Placement:
  the swapped cell if it is in the square (Candy-Crush "at the moved candy"), else the
  square's earliest `(row, col)` cell. Colour = the square's colour.
- **`Fish` is a new `SpecialKind` (tag `0x05`, char `F`).** Adding an enum variant
  does **not** re-lock existing vectors (the hash's special section only emits tag
  bytes for cells that carry a special, and no pre-B4 board has a fish). What re-locks
  the vectors is the **2×2-in-`find_matches`** change (deal/reshuffle/legality now see
  2×2s), not the enum.
- **Deal + reshuffle must avoid 2×2s.** `fill_no_initial_match` currently forbids only
  the colour that would complete a **line-3**; B4 also forbids the colour that would
  complete a **2×2** (up, left, up-left all that colour). So a settled board never
  starts with a free fish, and `reshuffle_if_dead`'s "no rest-matches" (which reads
  `find_matches`) already excludes 2×2 rest-matches. This changes the dealt board for
  every seed whose old fill placed a 2×2 → **all packs regenerate**, and the daily
  boards change (no users — acceptable; noted).
- **Fish activation = seeded targeting (B4.2, the first RNG-in-activation).** When a
  fish **fires** (matched, or swapped — `fires_on_match`/`fires_on_swap` += `Fish`), it
  targets **one** cell and clears it (plus its own cell). The target is chosen by a
  **pinned deterministic rule**: from the highest non-empty preference tier — (1) a
  **jellied** cell, else (2) a **blocker** cell, else (3) any **gem** — pick via
  `rng.index(candidates.len())` over the candidates in row-major order. The draw
  happens in `resolve_move` (which owns `self.rng`), per step, with fish processed in
  scan order, **before that step's refill**, so the RNG order is fixed and folded into
  `draws`/`state_hash`. A fish's target that holds a special **chains** (fires it).
  Minimal splash (target + fish cell only; a wider splash is revisable pre-users).
  - This makes activation **stateful in the RNG** for the first time — pinned in
    RULES T1c and re-locking the packs (activation now advances the stream before
    refill). The rule is deterministic and device-independent (integer `rng.index`).
- **Scoring stays flat:** +10 per gem cleared, +20 per blocker layer. A fish that eats
  a blocker cell — a blocker is not a gem, so eating it damages it via T2 (one layer),
  it is not "cleared to empty" by the fish directly (consistent with striped/wrapped
  hitting a blocker). *(Pin the fish-eats-blocker semantics in RULES T1c: the target
  is chosen from blockers only when no jelly remains, and the hit is one T2 layer.)*
- **Mandatory re-lock, at maximum.** The match-core change re-deals boards and shifts
  play; regenerate `games/match3/{par,blockers,jelly}-pack.json` **in the same commit**
  and expect the **blockers/jelly packs to change too this time** (their deals change),
  not just par. **Run the full gate** — the hardcoded JS fixtures (blockers/jelly
  seeds+moves in `match3-unit.test.ts`/`match3.spec.ts`, and the seed-based special
  e2e probes seed=3/11/13) will very likely go stale and must be re-derived (B0.4
  hazard, at its worst).

## Verified Assumptions

- `find_matches` is the single match authority read by `swap_legal`,
  `has_legal_move`, `legal_swaps`, `reshuffle_if_dead`, and the cascade loop. Confirmed
  by grepping call sites.
- `fill_no_initial_match` avoids line-3s cell-by-cell during fill; adding a 2×2 forbid
  is a local extension. `deal`/`deal_blockers`/`deal_jelly` all route through it.
  Confirmed by reading `engine.rs`.
- `creations_for` iterates run components (`find_runs`); a pure 2×2 has no runs, so
  fish creation needs a separate `find_squares` pass appended to `creations_for`.
  Confirmed.
- `SpecialKind` + `tag` + `from_char` (board.rs) and the hash special section
  (hash.rs) extend additively for `Fish` (tag `0x05`, char `F`) with no pre-B4
  re-lock. The wasm `BoardView.specials` string + `match3.ts` badge/a11y add a `fish`
  case. Confirmed by reading board.rs + the B0 render contract.
- Activation is currently a pure function; B4.2 threads `self.rng` targeting through
  `resolve_move` (as B2 threaded the re-blast seed). Confirmed.

### Phase 2 (B4.2) — fish activation (seeded targeting) + pack re-lock
**Goal:** a matched/swapped fish eats a target chosen by the pinned DetRng rule
(jelly → blocker → gem), chaining + cascading, deterministic; packs re-locked.
**Changes:**
- [ ] `engine.rs` — `fires_on_match`/`fires_on_swap` += `Fish`; a `fish_target(board,
  fish_pos, rng)` picking the tier + `rng.index` candidate; `resolve_move` draws
  targets for fired fish (scan order, before refill) and feeds them into `activate`'s
  clear set + chain queue. Keep the no-fish path byte-identical.
- [ ] `RULES.md` — T1c fish activation (tiers, RNG draw order, chaining, blocker rule).
- [ ] `tests` — a fired fish eats a jellied cell when jelly remains, else a blocker,
  else a gem; the draw is deterministic (two replays match; the fish is in the hash);

- [ ] golden vectors `15-fish-activate` (+ a jelly-target variant) locked; regenerate

**Risks:** activation now advances the RNG before refill → re-locks packs and every
activation vector's final hash. Keep the no-fish path identical (guarded by pre-B4
vectors). Pin the draw order precisely.
**Validation:** Broad — full gate + regen drills.
**Done when:** a fish eats a pinned-deterministic target + chains + cascades; all gates

  2×2), and only vector 14 in B4.2 (its created fish fires in its own cascade). The

  > gem; the built rule is jelly > any-gem (target always a gem, so `clear_cells` eats
  it and blocker damage still happens via the eaten gem's adjacency). Direct
  blocker-eating is a documented, revisable follow-up — it would need `clear_cells` to
  damage an in-set blocker.
- **First RNG-in-activation.** Fish targeting draws from `self.rng` in `resolve_move`
  (scan order, before refill) — the pinned draw order is the new determinism surface.
- **Fragile seed-based e2e.** The special-creation e2e tests pin magic seeds whose
  greedy line yields a given special within the 20-swap budget; the deal change broke
  the colour-bomb seed. Re-probing is the established fix, but a future refactor could
  make these tests seed-range-robust.
- **B5 (the combo matrix: special + special by swap) is next** — the last big specials
  phase, and where fish + special / bomb + bomb / etc. finally interact.
