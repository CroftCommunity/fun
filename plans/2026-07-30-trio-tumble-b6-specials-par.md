# Match-3 parity — Track B6: specials-exploiting strong player + re-par

**Status:** planning (2026-07-31). Parent: `plans/2026-07-30-trio-tumble-parity-roadmap.md`
(Track B / B6). Builds on B0–B5 (the full specials set + the combo matrix). B6 raises
the par ladder's **strong** rung to a player that deliberately builds and combos
specials, then re-bakes the committed par table.

## Problem Statement

The roadmap frames B6 as "teach the mode solvers about specials so packs stay winnable;
extend the par ladder's players to use specials." **Phase-0 discovery narrows this:**

- Both the winnability solvers (`find_clear`, `find_dejelly`) and all three par-ladder
  players (`random_score`, `reference_score`, `reference_score_beam`) already play the
  **real** engine (`legal_swaps` + `play_move`), so special creation, activation, and
  combos already fire in their playouts. B5's par-pack regen proved it — the beam 3★
  shifted because the beam player hit combos.
- The blockers/jelly packs stayed **byte-identical** across B1–B5, meaning those dailies
  win via plain play (specials optional) — so the winnability guarantee is not a lie; it
  is the *stronger* "winnable without needing specials".

So "make the solver understand specials" is already satisfied structurally. The genuine
remaining work (owner decision, 2026-07-31) is to make the **strong (3★) rung** a player
that *deliberately* exploits specials/combos, raising the ceiling, and re-grade the par
table in place (D5 — no users, no `VERSION` bump). This feeds Track C calibration.

## Decision locked (owner, 2026-07-31)

**Build a specials-exploiting strong player now** (chosen over "just lock the invariant"
and over "enhance the winnability solver's move-ordering"). It becomes the 3★ rung and
re-grades par in place.

## Reasoning

- **Why the current beam under-uses specials.** `reference_score_beam` ranks its
  width-8 frontier by cumulative **actual score**. Building a special often costs
  immediate score (a line-4 scores 3 cleared gems, not 4, and the payoff is a *later*
  blast), so special-building lines get pruned from a score-ranked frontier before they
  pay off. The beam therefore only takes combos that happen to fall out of
  high-immediate-score play.
- **Realization = a heuristic-guided beam (engineering choice, revisable).** A new
  `reference_score_specials` runs the same beam but ranks the frontier for **survival**
  by `actual_score + special_potential(board)` — a bonus for specials on the board and
  for combo-ready adjacent pairs — while still **reporting actual score**. So
  special-building lines survive pruning and get a chance to cash in, but the reported
  par is honest actual score. It **carries the beam-8 line as a floor**, so it provably
  scores **≥ the current 3★** (monotone, no regression risk in the "strong" direction).
  The `special_potential` weights are tunable knobs (Track C calibration territory).
- **Deterministic.** Fixed tie-breaks (stable sort; frontier + `legal_swaps` order are
  deterministic), integer arithmetic only, no wall-clock/float — so the baked table is
  bit-identical on every build target, like every other rung.
- **Re-grade in place (D5).** Swapping the 3★ rung re-derives every seed's 3★ at verify
  time, so the committed par table regenerates. No users exist → change par in place,
  `TrioTumble::VERSION` stays 1 (the versioning rule stays for the future).
- **"Strong-but-attainable" watch.** D5 set 3★ at strong-but-human-reachable, not
  near-optimal. A maximally-combo-exploiting player trends toward expert. Within the
  20-move target-score budget, building two colour bombs to combo (bomb+bomb = the whole
  board) is unlikely, so the realistic gain is from striped/wrapped combos (line-4s are
  reachable) — a moderate rise. **B6.2 measures the avg 3★ delta and reports it**; if it
  spikes toward near-optimal, that is a calibration flag for Track C (the owner tunes the
  weights or the rung), not a reason to withhold the build.

## Verified Assumptions

- `reference_score_beam` already carries the greedy line as a floor and returns the max
  cumulative actual score over a width-`beam` frontier. Confirmed by reading
  `trio-tumble-solver/src/lib.rs`.
- `par_tiers` composes 1★ = `random_score`, 2★ = `reference_score`, 3★ =
  `reference_score_beam(…, 8)`, forced strictly increasing. Confirmed.
- `Board`/`Game` expose `special_at` per cell (for `special_potential`) and `play_move`
  fires combos. Confirmed (B5).
- The par table is `include_bytes!`-embedded in the binding and regenerated by the
  `#[ignore]` generator; a byte-identical drill guards determinism. Confirmed.

## Phases

### Phase 1 (B6.1) — the specials-exploiting player (no par change yet)
**Goal:** a deterministic `reference_score_specials` that provably scores ≥ the beam-8
rung and deliberately favours special/combo-building lines. Not yet wired into par.
**Changes:**
- [ ] `trio-tumble-solver/src/lib.rs` — `special_potential(board) -> u64` (weight per special
  kind + a combo-ready-adjacent-pair bonus) and `reference_score_specials(seed, w, h,
  colors, budget, beam_width)` — a beam ranking the frontier by
  `actual_score + special_potential`, reporting max actual score, carrying the beam-8
  line as a floor.
- [ ] `tests` — it is deterministic (two runs match); it scores ≥ `reference_score_beam`
  for a spread of seeds; on a crafted seed where a combo line exists, it scores strictly
  more than the plain beam (it found the combo the beam pruned); monotone in budget.
**Validation:** Rust gate (`cargo test -p trio-tumble-solver`), fmt, clippy.
**Done when:** the player is deterministic + ≥ beam-8 + demonstrably combo-seeking; not
yet wired into par (no re-grade this phase).
